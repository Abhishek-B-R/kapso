Coding agents burn tokens and hand back diffs you have to review. Kapso runs them differently. You plug in a harness for your domain and set a goal; it works the goal until it is met, measuring every attempt with an evaluation the agents cannot touch and keeping every step on record. What comes back is a verified outcome: the branch that met the goal, the evaluation that proved it, ready to deploy as running software.

A harness teaches Kapso one kind of work: how to propose, build, measure and, where the domain needs it, deploy there, and the tools it needs. Two ship with Kapso, predictive modelling and competitive programming; the examples carry a trading harness, and you write your own for anything with an evaluation.

It learns from experience, and the lessons carry their receipts: one rule per card, the condition it applies under, the measured effect from each run that tested it, a reliability score with its rationale.

Kapso is an open-source Python framework by [Leeroo](https://leeroo.com). The source lives at [github.com/Leeroo-AI/kapso](https://github.com/Leeroo-AI/kapso) and the package installs with `pip install leeroo-kapso`.

## The whole thing in twelve lines

```python
from kapso import Kapso, Brief, Budget, Solution

kapso = Kapso()                                      # engine knobs from the packaged config
solution = kapso.build(
    Brief.read("kapso-brief.md"),                    # objective, how it is measured, baseline, target, rules
    evaluation="evaluation", data="data", repo=".",  # your evaluator (protected), your data, your code
    output="../churn-build", budget=Budget(minutes=60),
)
solution.score, solution.branch, solution.diff()     # what was delivered, how it measured, what changed
software = kapso.deploy(solution)                    # running software, locally or on a target
lesson = kapso.learn(solution)                       # what the campaign taught, banked with evidence
Solution.open("../churn-build")                      # the same solution, from any process
```

The same from a shell: `kapso build --brief kapso-brief.md --evaluation evaluation --data data --repo . --output ../churn-build --detach`, then `kapso watch ../churn-build --follow`. [Your first build](/docs/first-build) runs it on the churn example.

## The verbs

<CardGroup cols={2}>
  <Card title="Build" icon="hammer" href="/docs/build/brief">
    **`build()`** takes a brief and runs the campaign: candidates on their own branches, measured by an evaluator you provide or the campaign builds from your protocol, the best kept. When a session needs a credential or a file only you can provide, the campaign asks and pauses until you reply.
  </Card>
  <Card title="Deploy" icon="rocket" href="/docs/deploy/targets">
    **`deploy()`** turns a solution into running software, locally, in Docker, or on a cloud platform such as Modal.
  </Card>
  <Card title="Learn" icon="brain" href="/docs/learn/what-learn-produces">
    **`learn()`** mines a finished campaign into evidence-priced lesson cards the next campaign is served.
  </Card>
  <Card title="Experience" icon="magnifying-glass" href="/docs/experience">
    **`load_experience()`** names what a build is served: your bank, the hosted Leeroopedia gate, a bank your team shares, or a corpus **`add_experience()`** ingested from a repository or a researched question.
  </Card>
</CardGroup>

<Note>
  `learn()` mines your own finished campaigns into your bank; `add_experience()` ingests outside sources into an index. A build is served exactly what it loads.
</Note>

## What is inside

| Component | What it does |
|-----------|--------------|
| `Kapso` | The public API: `build`, `deploy`, `learn`, and the knowledge verbs |
| `Brief`, `Budget`, `Solution` | What a build takes and what it hands back, as objects and as files |
| Harness | The domain layer a build loads: pages, skills, tool servers, delegates and hooks, staged into every session |
| Orchestrator | Runs the experiment loop and tracks the budget |
| Search strategy | Explores candidate solutions as a tree |
| Coding agents | Pluggable implementers: Claude Code, Codex, Gemini, OpenHands, OSS Claude Code |
| Feedback generator | Validates each evaluation against the brief and decides when to stop |
| Evaluation registry | The evaluator versions a campaign measured with, provided or built, protected |
| Lesson bank | Evidence-priced cards mined from finished campaigns |
| Knowledge graph | Repository and research knowledge, searched over Weaviate and Neo4j |
| Repo memory | Evidence-backed understanding of an existing codebase |
| Deployment | Local, Docker, Modal, BentoML and LangGraph targets |

## Leeroopedia MCP

Kapso connects to [Leeroopedia](https://leeroopedia.com), a curated knowledge base of ML and AI frameworks. Agents query it during ideation and implementation to look up APIs, build plans and diagnose failures. See [Connect Leeroopedia](/docs/installation#connect-leeroopedia-recommended).
