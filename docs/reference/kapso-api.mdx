Everything public is importable from the top-level `kapso` package.

```python
from kapso import Kapso, Brief, Budget, Solution, Source, DeployStrategy

kapso = Kapso()
```

## Constructor

```python
Kapso(
    config: str | None = None,
    kg_index: str | None = None,
    bank: str | None = None,
)
```

| Argument | What it does | Default |
|----------|--------------|---------|
| `config` | Path to a config file: the engine's knobs, nothing else. Nothing starts here | the packaged `config.yaml` |
| `kg_index` | Path to an existing `.index` file. Without one, knowledge search is off | `None` |
| `bank` | Lesson-bank home directory. Overrides `learning.bank.local_path` | from config |

| Method | Returns | What it does |
|--------|---------|--------------|

| [`harness`](#load-harness) | `Harness \| None` | The loaded harness |
| [`build()`](#build) | `Solution` | Run an experiment campaign that meets a brief |

## load_harness

Loads a [harness](/docs/harnesses): the domain's pages, skills, tool
servers, delegates and hooks, staged into every session of the verbs that
follow.

```python
load_harness(ref: str) -> Harness
```

| Argument | What it does |
|----------|--------------|
| `ref` | A bundled name (`trading`), a directory (`./harnesses/trading`, read from the working directory), or a git reference (`git+https://github.com/acme/harnesses@v3#trading`, `acme/harnesses@v3#trading`) |

```python
harness = kapso.load_harness("../harnesses/trading")
harness.name, harness.version, harness.hash, harness.source   # the identity every record carries
harness.missing                                               # what this machine lacks, [] when nothing
kapso.harness                                                 # the same object, or None
```

It resolves the reference, fetching a git one into the store, runs `check` and raises `HarnessError` on a failure, hashes the directory, and reads what this machine lacks into `missing` without raising. A second call replaces the first: one object, one harness. Nothing starts here. The forms, the checks and the handle are in the [harness reference](/docs/reference/harness).

`build()` uses the loaded harness over the brief's `Harness` line, and refuses before any session while a need of the build's modules is unmet. `deploy()` and `learn()` take the harness from the solution's record when none is loaded; a loaded one of the same name is used instead, another version included; another name is refused.

## build

Runs the experiment campaign: propose a candidate, implement it on its own
branch, measure it, keep the best, repeat until the objective is met or the
budget is spent.

```python
build(
    brief: str | Brief | None = None,
    *,
    evaluation: str | None = None,
    data: str | None = None,
    repo: str | None = None,
    output: str | None = None,
    budget: Budget | None = None,
    resume: bool = False,
    on_status = None,
    iteration_evaluator: IterationEvaluator | None = None,
    iteration_evaluator_failure_policy: str = "record",
    mode: str | None = None,
    coding_agent: str | None = None,
    context: list | None = None,
    additional_context: str = "",
    serving_scope: dict | None = None,
) -> Solution
```

| Argument | What it does | Default |
|----------|--------------|---------|
| `brief` | A sentence, or a `Brief`. A sentence becomes a brief with only an objective. The whole brief reaches the engine, never clipped. Left out only on a resume, which takes it from the checkpoint | `None` |
| `evaluation` | Directory holding your evaluator; copied to `kapso_evaluation/` and protected | `None` |
| `data` | Directory holding your data; copied to `kapso_datasets/` | `None` |
| `repo` | The starting repository: a local path (copied, never modified) or a GitHub URL (cloned). `None` starts empty, or from a workflow the knowledge graph knows | `None` |
| `output` | The campaign directory, the solution's `trace`. Empty for a fresh build; the campaign itself for a resume | a temporary directory |
| `budget` | What the build may spend. Its set fields win over the brief's `Budget` line; on a resume the launch record fills what is still unset; the config's defaults fill the rest | `None` |
| `resume` | Continue the campaign in `output` from its checkpoint. The mode, coding agent, evaluation, config and knowledge index must match the launch's; a difference is refused by name | `False` |
| `on_status` | Callback fired after every status write and heartbeat | `None` |
| `iteration_evaluator` | Score every finalized candidate with your own evaluator, in an isolated worktree | `None` |
| `iteration_evaluator_failure_policy` | `record` stores your evaluator's error on the candidate; `raise` stops the run | `"record"` |
| `mode` | Config mode, `GENERIC` or `MINIMAL` | from config |
| `coding_agent` | Override the agent that writes code | from config |
| `context` | Extra context passed to the campaign, such as research findings | `None` |
| `additional_context` | Free text appended to the campaign context | `""` |
| `serving_scope` | Restrict which banked lessons are served | `None` |

```python
solution = kapso.build(
    Brief.read("kapso-brief.md"),
    evaluation="evaluation", data="data", repo=".",
    output="../churn-build", budget=Budget(minutes=60),
)
print(solution.explain())
```

`build()` blocks for the whole campaign and writes the solution to
`<output>/.kapso/solution.json` when it returns, so
[`Solution.open`](#solution) reads it from any process. From a shell, prefer
`kapso build --detach` and `kapso watch`.

### Brief

The brief as an object; the same grammar as the `kapso-brief.md` file. See
the [brief format](/docs/reference/brief-format).

```python
@dataclass
class Brief:
    objective: str
    measured_by: str | None = None
    baseline: str | None = None
    target: str | None = None
    rules: list[str] = []
    budget: Budget | None = None
    harness: str | None = None
    experience: list[str] = []

Brief.read(path) -> Brief        # parse the file; an unknown or repeated field, a missing
                                 # objective or stray text raises BriefError with the line
Brief.parse(text) -> Brief
brief.render() -> str            # the file's text, deterministic: what the engine receives
brief.write(path) -> Path
```

### Budget

```python
@dataclass
class Budget:
    minutes: float | None = None           # wall clock, durable across resumes
    experiments: int | None = None         # experiments this call may run
    usd: float | None = None               # model spend, USD
    reserve_minutes: float | None = None   # escrowed for the final checkout and evaluation
```

Every field optional; a field left `None` keeps the brief's, the launch's
or the config's value. Values are validated: positive and finite, an
integer count, a reserve smaller than the minutes.

### Solution

What a build delivered and the account of how. Returned by `build()` and
read back by `Solution.open(path)`.

| Attribute | Type | What it holds |
|-----------|------|---------------|
| `brief` | `Brief` | The brief the build ran |
| `campaign` | `Path` | The campaign directory, checked out at the delivered branch, with the record under `.kapso/` |
| `branch` | `str \| None` | The delivered candidate's branch; `None` when no candidate succeeded |
| `commit` | `str \| None` | Its commit at delivery |
| `base_commit` | `str` | The seed commit, `diff()`'s base |
| `score` | `float \| None` | The delivered candidate's measurement under the registered evaluator |
| `goal_achieved` | `bool` | The judge's verdict that the objective was met |
| `stopped_reason` | `str` | `goal_achieved`, `max_iterations`, `budget_exhausted`, `waiting_for_user` |
| `stop_detail` | `str \| None` | Which budget dial stopped it, when one did |
| `experiments`, `experiments_total` | `int` | Experiments this call, and across every resume |
| `cost_usd` | `float` | Model spend |
| `requests` | `list[dict]` | What you must answer when `stopped_reason` is `waiting_for_user`; empty otherwise |
| `feedback` | `str \| None` | The last judgment, in full |
| `evaluator` | `EvaluatorRef \| None` | `version`, `evaluator_id`, `provenance` of the evaluator the score was measured under; `None` when none was registered |
| `harness` | `HarnessRef \| None` | `name`, `version`, `hash`, `source` of the harness the build ran with; `None` without one |
| `verification` | `dict \| None` | The harness's verdict on the delivered candidate: `verdict`, `summary`, `findings`; `None` when no verification ran |
| `experience` | | The experience sources the build ran with, as that feature ships |
| `rejected_candidates` | `int` | Candidates rejected: the judge found the evaluation invalid, the evaluator was touched, or the harness voided the attempt |
| `callback_metrics`, `callback_primary_metric` | `dict`, `str \| None` | Your own `iteration_evaluator`'s numbers for the delivered candidate |
| `knowledge_index`, `experience_head` | `str \| None` | The knowledge index and the lesson-bank commit the build drew on |

```python
Solution.open(path) -> Solution   # the record a build wrote in that directory;
                                  # raises before the build has returned, naming kapso watch
solution.explain() -> str         # the summary block
solution.diff() -> str            # git diff from the seed to the delivered commit; "" when none
```

### inbox and reply

A campaign pauses when a session needs something only you can provide; see
[the inbox](/docs/build/inbox). Two static methods act on a paused campaign
directory.

```python
Kapso.inbox(campaign: str) -> list[Request]
Kapso.inbox_ideas(campaign: str) -> dict[int, str]
Kapso.reply(campaign: str, request_id: int, note: str = "", *, allow_secret: bool = False) -> Solution | None
```

`inbox` returns the open requests, oldest first, each with `id`, `key`, `hit`, `tried`, `fix` and `next_steps`. `inbox_ideas` returns one line per node of the campaign, the idea a request was made for, keyed by node id; `kapso inbox` prints it as the `for` row. `reply` records the note and, once every request of the node that asked is answered, resumes the campaign in this process and returns its result. It returns `None` when another request of that node is still open, or when the campaign was started with an `iteration_evaluator`: the callback lives in your script, so call `build()` again there with `resume=True`. It raises while a live process holds the campaign, and raises on a note shaped like a credential unless `allow_secret=True`: replies are plain text handed to the coder, so a value belongs in the `.env` the request's `fix` names.

## research

```python
research(
    objective: str,
    *,
    mode: ResearchMode | list[ResearchMode] = ["idea", "implementation"],
    depth: ResearchDepth = "deep",
) -> ResearchFindings
```

| Argument | What it does | Default |
|----------|--------------|---------|
| `objective` | What to research | required |
| `mode` | `"idea"`, `"implementation"` or `"study"`, or a list of them | `["idea", "implementation"]` |
| `depth` | `"light"` or `"deep"` | `"deep"` |

`mode` and `depth` are keyword-only.

```python
findings = kapso.research(
    "QLoRA fine-tuning memory optimizations",
    mode=["idea", "implementation"],
    depth="deep",
)
```

### ResearchFindings

| Attribute | Type | What it holds |
|-----------|------|---------------|
| `query` | `str` | The objective you gave it |
| `ideas` | `list[Source.Idea]` | Approaches found |
| `implementations` | `list[Source.Implementation]` | Implementation references, with code |
| `report` | `Source.ResearchReport \| None` | Present when `mode` included `"study"` |
| `to_string()` | `str` | Findings as text, ready to pass as `build(..., context=[...])` |
| `to_dict()` | `dict` | The same as plain data |

## learn

Learns from one finished campaign: import it, mine it, grade the bank against it, then fold the result in as evidence-priced cards.

```python
learn(
    source: Solution | str,
    *,
    trajectory_id: str | None = None,
    learner_version: str | None = None,
    exam: bool = True,
    push: bool | None = None,
    on_status = None,
) -> LessonResult
```

| Argument | What it does | Default |
|----------|--------------|---------|
| `source` | A `Solution` (its `trace` is read directly), a path to a campaign directory, or a trajectory id already in the store | required |
| `trajectory_id` | Store id when importing a directory | derived from the objective or directory name |
| `learner_version` | Update-crew version | `learning.update_crew.default_version` |
| `exam` | Run the hindcast exam against the pinned pre-lesson bank head first. `False` is for development replays only | `True` |
| `push` | Push the bank commit to the bank's `origin` remote | auto: pushes when the bank has an `origin` remote |
| `on_status` | Callback fired on each status heartbeat | `None` |

```python
lesson = kapso.learn(solution)
print(lesson.explain())
```

On a campaign built with a harness, the learning module's pages join the mining and update crews' prompts, and the trajectory manifest records the build's harness and, when it differs, the one the lesson ran with.

### LessonResult

| Attribute | Type | What it holds |
|-----------|------|---------------|
| `trajectory_id` | `str` | Id of the trajectory that was learned from |
| `bank_head_after` | `str` | Bank commit written by this lesson |
| `cards_created` | `list[str]` | New cards the update crew wrote |
| `cards_updated` | `list[str]` | Existing cards the lesson modified |
| `exam_report_path` | `str \| None` | Hindcast exam report, when `exam=True` |
| `lesson_report_path` | `str \| None` | The lesson report |
| `admitted` | `bool` | Whether the lesson was admitted to the bank |
| `explain()` | `str` | The above as readable text |

## learn_knowledge

Folds outside sources into the knowledge graph. This is the other memory: `learn()` mines your own campaigns, `learn_knowledge()` imports other people's work.

```python
learn_knowledge(
    *sources: Source.Repo | Source.Solution | Source.Idea
            | Source.Implementation | Source.ResearchReport | ResearchFindings,
    wiki_dir: str = "data/wikis",
    skip_merge: bool = False,
    kg_index: str | None = None,
    github_org: str | None = None,
    is_private: bool | None = None,
    on_status = None,
) -> PipelineResult
```

| Argument | What it does | Default |
|----------|--------------|---------|
| `*sources` | One or more sources. A `ResearchFindings` can be passed directly | required |
| `wiki_dir` | Where extracted wiki pages are written | `"data/wikis"` |
| `skip_merge` | Extract pages without merging them into the graph | `False` |
| `kg_index` | Index to merge into | from the constructor |
| `github_org` | Organisation to publish the extracted workflows' repositories to; passing it turns publishing on for this call (`learner.ingestor.publish_workflows` otherwise) | `None` |
| `is_private` | Whether those repositories are private; passing it turns publishing on too | from config |

A run that stops keeps its clone and finished phases under `<wiki_dir>/_staging/<repo>/<branch>`; calling `learn_knowledge()` again with the same source continues from the first unfinished phase.

```python
kapso.learn_knowledge(
    Source.Repo("https://github.com/huggingface/trl"),
    findings,
    wiki_dir="data/wikis",
)
```

### Source variants

| Variant | Takes |
|---------|-------|
| `Source.Repo(url, branch=None)` | A repository URL; its default branch unless `branch` names one |
| `Source.Solution(obj)` | A `Solution` |
| `Source.Idea(query, source, content)` | A research idea |
| `Source.Implementation(query, source, content)` | An implementation reference |
| `Source.ResearchReport(...)` | A study-mode research report |

### PipelineResult

| Attribute | Type | What it holds |
|-----------|------|---------------|
| `sources_processed` | `int` | How many sources were read |
| `total_pages_extracted` | `int` | Wiki pages produced |
| `extracted_pages` | `list[WikiPage]` | The pages themselves |
| `merge_result` | `MergeResult \| None` | What the merge changed |
| `errors` | `list[str]` | Anything that failed |
| `created` / `edited` | `int` | Counts of pages the merge created and edited |
| `success` | `bool` | No errors, or pages were still extracted despite them |

## deploy

```python
deploy(
    solution: Solution,
    strategy: DeployStrategy = DeployStrategy.AUTO,
    env_vars: dict[str, str] | None = None,
    coding_agent: str | None = None,
    model: str | None = None,
) -> Software
```

| Argument | What it does | Default |
|----------|--------------|---------|
| `solution` | The `Solution` from `build()`, or `Solution.open(path)` | required |
| `strategy` | `AUTO`, `LOCAL`, `DOCKER`, `MODAL`, `BENTOML` or `LANGGRAPH` | `AUTO` |
| `env_vars` | Environment variables for the deployed software | `None` |
| `coding_agent` | Agent behind the selector and adapter sessions | from config (`deployment.coding_agent`) |
| `model` | The model that agent is asked for | from config (`deployment.model`) |

```python
deployed = kapso.deploy(solution, strategy=DeployStrategy.LOCAL)
result = deployed.run({"data_path": "./test.csv"})
deployed.stop()
```

`AUTO` picks a strategy for you. See [Deployment strategies](/docs/deployment/strategies). On a solution built with a harness, the selector and the adapter carry its deployment module: the pages in their prompts, its skills, servers and hooks beside them (see [Use a harness](/docs/harnesses/use#deploy-and-learn)).

## index_kg

Indexes a corpus and returns the path of the `.index` file it wrote.

```python
index_kg(
    wiki_dir: str | None = None,
    data_path: str | None = None,
    save_to: str = None,
    search_type: str | None = None,
    force: bool = False,
) -> str
```

| Argument | What it does | Default |
|----------|--------------|---------|
| `wiki_dir` | Wiki directory to index | `None` |
| `data_path` | JSON data file to index, as an alternative to `wiki_dir` | `None` |
| `save_to` | Where to write the `.index` file | required in practice |
| `search_type` | `kg_graph_search` or `kg_llm_navigation` | from config |
| `force` | Clear existing data before indexing | `False` |

```python
index_path = kapso.index_kg(
    wiki_dir="data/wikis",
    save_to="data/indexes/finetuning.index",
)

kapso = Kapso(kg_index=index_path)
```

## memory

A property, not a method. Reports what this agent knows across both stores.

```python
status = kapso.memory
print(status.explain())
```

| Attribute | Type | What it holds |
|-----------|------|---------------|
| `knowledge_index` | `str \| None` | The loaded `.index`, if any |
| `knowledge_enabled` | `bool` | Whether knowledge search is on |
| `bank_head` | `str \| None` | Current lesson-bank commit |
| `store_trajectories` | `int \| None` | Trajectories in the store |
| `explain()` | `str` | The above as readable text |

## status

A static method. Reading a run needs no constructed agent.

```python
Kapso.status(path: str) -> OperationStatusView
```

```python
view = Kapso.status("./campaign")
print(view.explain())
```

`path` accepts a workspace, a status file, or a directory of status files. `view.explain()` renders the same screen as [`kapso watch`](/docs/reference/cli#kapso-watch).

## close

Releases the knowledge-search network clients: Weaviate, Neo4j and embeddings.

```python
kapso.close()
```

Idempotent, and registered at construction to run on exit, so scripts finish without unclosed-socket warnings. Calling it early is safe; `index_kg()` and `learn_knowledge()` reconnect.
