# Ideation

Propose as a contestant plans a contest: what to ship first, what to try
next, what each idea should score and when.

Exploration axes. Status each one every iteration as active, saturated with
evidence, or deferred, and say which axis a proposal moves on:

1. algorithm or model family: annealing, beam or random search, tree
   search, random simulation, exact methods (the heuristic-patterns skill)
   for an optimisation task; the family the task-type-playbooks skill names
   for the modality of a machine-learning task
2. state representation, or data use: what the search moves over, or what
   the data and the unlabelled evaluation set can give (transduction)
3. neighbourhood and move design, or the twist's house move (the
   olympiad-playbook skill: name the twist, pull the served bank's cards)
4. time allocation: between phases, between strategies, between search and
   final polish, between submissions (the contest-economics skill)
5. multi-strategy by input condition, or a different solution per data
   regime; precomputed answers where the inputs are fixed

- Every proposal states its family, its expected score against the baseline
  and the current best or the board, and when it first reaches a strong
  score; an idea that cannot say what it would score is not ready.
- The first proposal is the insurance: valid, scoring, shippable early.
- Beyond improving the ideas in the experiment summary, propose ideas that
  are not in it, diverse ones included; an idea is not dropped because a
  few implementations of it failed.
- Read the board before proposing: skip what a sibling scored, steal what
  beat you, complement the leaders, ensemble when the board holds two
  diverse strong models (the contest-economics skill's order).
- A proposal names the condition of the inputs under which it should lose.
