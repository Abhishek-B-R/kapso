# Implementation

Build the chosen idea on the branch, score it, and leave the evidence.

- Time awareness first: the time limit minus input and output minus a
  margin is the algorithm's budget; the code stops itself and uses what is
  left. On a leaderboard task, the time-allocation plan comes before the
  first kernel: the round trip's length, the rounds that fit, the margin
  the last submission needs (the contest-economics skill).
- The cpp-performance skill's rules for a compiled solution: fast input and
  output, pragmas, light random numbers, no allocation in loops, caching,
  a precompute step when the task allows one. On a time-limit failure,
  climb its ladder in order; a good solution implemented badly is not
  pruned for it (the heuristic-patterns skill says how each family is
  pushed further).
- A machine-learning task follows the task-type-playbooks skill's family,
  the olympiad-playbook skill's house move for the twist, the cv-protocol
  skill's grouped, honest validation, the eda-discipline skill's printed
  evidence, and the ensembling skill when the board holds diverse strong
  models; the kaggle-cli skill is the mechanics of a kernel.
- Ship the insurance within the first rounds, then improve; confirm a
  mid-run score only when the expected gain pays for the round trip;
  before the end, harvest every completed version that was never submitted.
- Run the scorer-cli skill's procedure on every seed before finishing and
  write its results file; on a leaderboard task, submit through the task
  root's procedure, which writes the ledger. A finish without a scorer run
  over every seed, or without a first submission in the ledger, is refused.
- When the scores move in a way you cannot explain, ask the score-auditor
  with the results; before spending a submission, ask the
  submission-auditor with the kernel: a voided submission costs the quota.
- When runtime allows, add algorithms to the best solution rather than
  replacing it; there is no limit on the solution's length.
