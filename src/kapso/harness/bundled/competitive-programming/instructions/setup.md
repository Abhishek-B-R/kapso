# Setup

Pin what every later session will see, then write the domain statement. Do
not write a solution in setup.

1. Read the task root the task statement names: the problem statement with
   its examples and constraints, the scorer or the submission procedure,
   the seeds or cases, the baseline, the quota and the deadline, the
   organizers' rules. When no root exists because the task arrived as a
   URL or an organizers' brief, the contest-preflight skill says what a
   complete one holds.
2. Run the scorer once on the baseline with the scorer-cli skill to learn
   its invocation, its output and the score's units and direction, or, on
   a leaderboard task, read the board and the submissions list with the
   kaggle-cli skill to learn the modality, the format and what the account
   has already spent.
3. Write the domain statement: the problem's kind (heuristic optimisation,
   an exact algorithm, a machine-learning task under contest rules, and
   its twist); the input distribution and the largest inputs the
   constraints allow; the time and memory limits with the margin to keep;
   the compile and run lines or the kernel's fixed environment; the scorer
   or the leaderboard, its units and direction; the seeds and the
   baseline's scores, or the board's best and the account's history; the
   submission form and modality; the quota, the deadline and the session
   limits; the compute here and on the scoring side; the time-allocation
   plan's inputs (the round trip's length).
