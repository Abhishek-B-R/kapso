# Setup

Pin what every later session will see, then write the domain statement. Do
not write a solution in setup.

1. Read the task root the task statement names: the problem statement with
   its examples and constraints, the scorer or the submission procedure,
   the seeds or cases, the baseline, the quota and the deadline.
2. Run the scorer once on the baseline with the scorer-cli skill to learn
   its invocation, its output and the score's units and direction; record
   the baseline's score per seed and its runtime.
3. Write the domain statement: the problem's kind (heuristic optimisation,
   an exact algorithm, a machine-learning task under contest rules); the
   input distribution and the largest inputs the constraints allow; the
   time and memory limits with the margin to keep; the compile and run
   lines; the scorer's invocation, units and direction; the seeds and the
   baseline's scores; the submission form (which file, where, how it is
   judged); the quota, the deadline and the session limits when the task
   names them; the compute.
