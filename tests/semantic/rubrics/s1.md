# S1: the cold engineer's flow, judged

A model with no Kapso knowledge, given only the public docs, attempted six tasks in Python and on the command line and then answered comprehension questions (docs/plans/semantic-production-tests.md, section 2). You hold two files and nothing else: the engineer's comprehension answers with the key beneath them (what each call did, what it returned, where the record is), and the flows the engineer wrote (per attempt, the script run with its code-line count, or the commands run, beside the attempt's own figures); cite only those. Score each judgment 0 or 1:

- **names say what the calls do**: 1 when the engineer's comprehension answers name what each call (build, deploy, learn, resume, the harness load, the evaluator) does and returns, and where the record is, matching the key given below the answers, with no name that surprised the engineer (such as a loader that ingests); cite any call answered wrongly. This dimension is the comprehension verdict the suite reads.
- **the flows fit the design's lengths**: 1 when the whole Python flow fits in twelve lines and the CLI flow in six commands, as the flows file shows (the longest task's script in code lines, the longest task's commands); cite the script or the commands that decide it.
- **nothing needed the docs do not say**: 1 when every step the engineer needed is in the docs it was given; cite the gap when there was one.
