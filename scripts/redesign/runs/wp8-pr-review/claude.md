## Findings

**1. P1 — the abstraction gate and the vocabulary test error at collection on CI, because the "dependency-free" vocabulary is not dependency-free.**
`benchmarks/harness_scan.py:26` imports `benchmarks.relbench.task_specs`, and `benchmarks/relbench/task_specs.py:14` does `from relbench.base import AutoCompleteTask, RecommendationTask, TaskType` at module level. `tests/test_bundled_abstraction.py:13` and `tests/test_benchmark_vocabularies.py:15-16` import that chain with no guard, while every other benchmark test file guards itself (`tests/test_relbench_integration.py:20`, `test_mle_benchmark.py:15`, `test_ale_benchmark.py:18`) precisely because `.github/workflows/tests.yml:46` installs only `-e '.[dev]' numpy pandas` — no relbench, mlebench or ale_bench, and `dev` is pytest/cov/black/flake8 (`pyproject.toml:95-101`). So the gate that the plan says "runs unconditionally and fails on a hit" (plan 303-305, 688-689) is a `ModuleNotFoundError` at collection in CI, which fails the suite for a reason that has nothing to do with the harnesses, and `test_benchmark_vocabularies.py`'s own docstring promise ("Each skips when its registry is absent") is defeated by its module-level import. Acceptance "the gate green at every merge" is unmet.
*Fix:* move the RelBench names the scan needs into committed data with no library import — a `benchmarks/relbench/datasets.py` beside `ale/problems.py`, or a `data/datasets.json` like MLE's and IOAI's — have `vocabulary()` read that, and let `test_benchmark_vocabularies` check the file against `relbench.datasets` under its existing `importorskip`.

`scripts/redesign/runs/s3-1/arms.json:10-19` has `arm-relbench`, `arm-mle`, `arm-ale`, `swap-ale`, `swap-ioai` as `null`; only `arm-ioai`, `swap-relbench` and `swap-kaggle` are recorded. `tests/semantic/suite.json:350-361` requires all nine for host `machine`, `scripts/redesign/s3_ports.py:240-243` records a null run as deferred, and `tests/semantic/reports/s3-1.md` does not exist — so S3's verdict today is a fail, and changes 19–22 carry no Done notes. The plan's Acceptance (800-844) still asserts "The four arms recorded on the frozen versions", "The task swaps at zero harness edits … the two Kaggle swaps' quota cost recorded" and "The author test at zero structural guesses", none of which the tree evidences. The arm notes (1190-1246) do say three arms died and were relaunched, but that paragraph is the only place a reader learns the acceptance is open.
*Fix:* before merge, either finish and record the remaining arms and swaps, or state in Acceptance and in MASTER's row exactly which steps are deferred and what the merge rests on (the scan, the two harness reviews, the two clean swaps, the one IOAI arm), and run `s3_ports.py --rederive` so `reports/s3-1.md` exists with the deferred steps visible rather than absent.

**3. P2 — a successful submission can be recorded as rejected: the verdict is a substring match over the whole CLI output.**
`benchmarks/ioai2026/submit.py:36-45` returns `rejected-400` when `"400" in blob` and `rejected-403` when `"403" in blob`, where `blob` is stdout+stderr of `kaggle competitions submit` — which carries an upload progress bar (`400k/400k`, `2.40M`) and, on some CLI versions, the message the procedure just minted (the skill *requires* the local score in it: `local=0.4003` contains `400`). A false `rejected` writes `status: "rejected"` into the ledger, exits 2, and `data/generic_eval/evaluate.py:128-130` then reports the candidate rejected (exit 13) although the submission is live and will score — the experiment is lost and the ledger, which the verifier and `require-insurance` read, carries a false record. `benchmarks/ioai2026/runner.py:282-293` is the same classifier, used by the harvest's version probe, where a false "accepted" or "rejected" also misdirects.
*Fix:* classify on the CLI's own success phrase, or match a status with boundaries on stderr only (`\b(400|403)\b`), and treat anything unrecognised as `pending` rather than `rejected` — the token in the message is exactly what lets `refresh()` settle it from the submissions list.

**4. P2 — `tests/test_bundled_scripts.py` skips its whole file without relbench, including the leakage-scan rules that need no library.**
`tests/test_bundled_scripts.py:142` puts `pytest.importorskip("relbench")` mid-module, after the scan tests (lines 33-133) and before the sanitizer tests. A module-level skip skips the file, so on CI the twelve violation rules, the three regimes, the advisory/violation exit codes, the tree-mode exclusions and the diff line numbering are never exercised — the part of the suite that actually protects a candidate-facing script.
*Fix:* keep the scan tests unconditional (their own module, or move the sanitizer tests into `tests/test_bundled_sanitizer.py` with the `importorskip` at its top).

**5. P2 — the MLE score of record is the candidate's own printed number, and nothing in the loop can contradict it.**
`benchmarks/mle/data/generic_eval/grader.py:129-135` takes the last `<score>…</score>` the candidate printed as the manifest's `score`/`raw_score`; `benchmarks/mle/context.py:20-28` asks the candidate to hold back its own stratified ten percent and print the number. The grader validates the submission's *format* (`check_submission`) but computes no metric, so a candidate that reports an optimistic hold-out wins selection, becomes the parent, and is only contradicted by the official private grade after the campaign — on a 24 h arm that is the whole budget. RelBench, ALE and IOAI all have an evaluator-owned number (official metrics, the Docker judge, the leaderboard); MLE is the one benchmark where the search optimises a self-report. The plan treats this as settled (C15/L6, decision "the held-out score stays the search signal"), but the honesty question is not the *choice of metric*, it is that the evaluation cannot verify it.
*Fix (owner's call, worth stating either way):* have the grader own the split — derive the hold-out ids deterministically from `task.json` (seed + stratification column), pass them to the candidate as the file it must not train on, and score the predictions it writes for those rows — or, at minimum, record in the plan that the in-loop number is self-reported and that only the verifier and the final grade check it.

## What came out clean

- **The two harnesses are domain harnesses.** Every page and skill routes by situation ("when the data is a relational database with a temporal cutoff", "where the task is scored on a leaderboard"); no evaluator, dataset, goal, budget, credential value, engine field, or model/runner choice for Kapso's own agents; no benchmark, task, dataset, competition or problem name; every number I found is either spelled out, fenced, or a domain fact (a checkpoint's sampling rate), and the practices read as measurements with their conditions. What the scan can never catch, and what the pages do still carry: the data library's name reachable through a skill's own name (`setup.md:35`, `implementation.md:10` say "the relbench-api skill", and `own_names` blanks it before a word is read), the platform names Kaggle and AtCoder (domain vocabulary by decision — `kaggle-cli` is a whole skill about one platform's CLI, which the "domain commands" clause allows), and the standing leans stated flatly on the guardrails ("features before architectures", "an ensemble comes last") that the practices skill frames as leanings.
- **The engine facts the pages assert are true.** `KAPSO_HARNESS_ROOT`, `${PLUGIN_ROOT}`, `prepared/`, `kapso_task.md`, `kapso_datasets/`, `results/` as a harness convention, `$KAPSO_SHARED_CACHE_DIR` (a real engine variable, injected set-if-absent into every session including the setup session's `env_defaults`), both hosts' PreToolUse deny shape and the top-level `{"decision":"block"}` Stop shape with `stop_hook_active` — all check out against `write.mdx`, `staging.py` and `shared_cache.py`. The hooks run from the session directory, which is what makes `Path.cwd()/prepared` and the task-root walk correct, and the session copies do carry `kapso_task.md` and `kapso_datasets/` (confirmed in the arms' trees).
- **The hooks.** Each is conditional on what the task root provides, so neither harness blocks the other's modality; both Stop hooks honour `stop_hook_active` and say how to finish when they cannot be satisfied; the shell denial fires only where a procedure is named, and its pattern covers the path, the alias, the continuation and the Python API; the corrupt-evidence path fails loud and the `|| exit 2` launcher turns it into a block, tested through `bash -c`. The predictive-modelling hooks have no `|| exit 2`, which matches the engine's own `protect-harness` and is the right asymmetry: a crashed PreToolUse deny falls back to the engine's permission boundary, a crashed Stop hook would pass a finish.
- **The runners.** Each launches `build()` with its bundled harness, its Brief from the task's own facts (every schema column listed, the statement verbatim, nothing clipped), its evaluation staged with a committed `task.json`, its budget mapped flag by flag; `honor_agent_stop: false` in all four override files, with a test over all four; the literals the handlers carried are in the `benchmark:` block and read at the call site; no `os.environ` read in any runner; the oriented score with the raw metric beside it in every grader and both in `Measured by`; the floors from config; ALE's all-or-nothing rule in the task statement rather than the harness; IOAI's attribution by kernel/file hash with five distinct outcomes, tested through the real `evaluate.py` against a fake CLI; `label_run_of_record` correctly inert for the three benchmarks with no archive glob.
- **The bank extension is honest.** `reported` sits outside `EXECUTED_VERDICTS`, so it promotes nothing, seeds no codify, and lands in no probe tier (`exposure` needs a serving usage, `outcomes` needs confirm/weaken/refute); conformance demands all five source fields with `score` nullable; admission refuses the verdict by name with a reason; the retriever renders the source whole and stamps every read of a reported-only card; the converter writes the bank whole after every check, refuses markdown in a payload, keeps the confidence line in sync with `reliability.plain`, and the test loads the result through `load_experience` and reads the card and its code payload. The arm's pull log shows 46 cards served minus the task's own entry, every one `score: null`.
- **The two engine fixes.** `stream_lines` splits on the newline alone and every stream reader goes through it (the one remaining `splitlines` in the adapters is over a `git` listing, and `update_frame` feeds a file object, which splits on `\n` already); the cut-line test plants U+2028, U+2029, U+0085 and a form feed. `commit_folder`'s `git add -f` is the right call and its test reproduces the arm's exact ignore rule.
- **The tests earn their place.** The runner tests enter the real facade with the provider boundary mocked and pin the launch record, the staged settings, the runtime file, the roles and the seeded candidate; the hook tests drive both hosts' event shapes and the launcher; the scan tests pin one finding per rule; `test_bundled_harnesses` adds the tracked-file check that the `*cache*/` ignore trap earned. The six shared skills are kept byte-identical by a gate test, and the harness hash pinned in the plan is the one the Kaggle swap's session records carry.
- **The docs sentences** in `use.mdx`, `write.mdx`, `cli.mdx`, `kapso-api.mdx`, `configuration.mdx` and the four benchmark pages and READMEs are accurate against the code I read (including the defaults they quote), and the `.gitignore` re-include is in the one form git honours for a directory.
